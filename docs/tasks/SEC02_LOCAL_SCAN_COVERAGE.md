## 静态审查结论
1. 高优先级：`packages/core/src/tools/sensitive-content-access-policy.ts` 的 DefaultDlpScanner 使用 content.slice(0, 256 * 1024)；常量称 BYTES，实际为 UTF-16 code units。尾部未扫描仍返回 isSensitive:false，不能代表完整内容安全。
2. 规则覆盖缺口：DLP 与 `infra/redaction.ts` 分别维护规则；前者没有后者的裸 sk- 规则，后者没有前者的完整私钥/连接串覆盖。不能以其中一层代替另一层。
3. 需装配核查：`tools/builtins.ts` 的 assertSensitiveContentAllowed 在策略缺失时直接返回，gitReadonlyView 也条件调用。已发现正常注入和集成测试文件，但本轮未证明每个生产构造路径均不可漏装。
4. 身份声明需核查：解析器获得 dev+ino 且有 isSameResource，但 matchSensitivePath 本身只比较路径视图；不能仅凭取得 inode 宣称硬链接别名已拦截。lstat/stat 异常存在吞掉分支。
5. 本次没有读取真实凭据，也没有扫描用户真实敏感文件；上述为代码审查，不是已发生泄露结论。

## 01：完整扫描结果契约（优先实施）
替换“未命中即安全”为 clean / sensitive / incomplete / error，附规则版本、扫描范围、真实字节数、限制原因；旧调用方仅 clean 可继续。以 UTF-8 字节计量；大内容分块扫描或返回 incomplete，不默默截尾放行。跨块规则需状态机/有限最大匹配跨度，不能依赖随意的固定重叠长度保证多行私钥完整扫描。
每次限时/限内存；超限、未知编码、解码失败、不可支持容器返回 incomplete。扫描前不流出首块；所有将发往模型或外部的内容先完成相应检查。流式输出使用有界隔离缓冲，不能先发送后发现。

## 02：规则与出口策略统一
建立版本化检测器注册表，分别产生“阻断模型读取”和“日志掩码”策略，不能把全部内容脱敏后自动放行敏感文件。覆盖已支持厂商格式、Authorization/Cookie、GitHub 新旧 token 形态、私钥含多行与加密头、连接串、结构化敏感字段。只用人工构造假凭据。
高熵只作为补充信号，不以熵高低单独证明泄露/安全；泛 token 字段如普通标识应减少误报。测试假值豁免只限测试夹具，不开放全模式禁读绕过。规则测试不联网验证 token 是否可用。
错误/诊断只报告类别、范围和规则版本，不打印命中值、前后文、可逆摘要；不以裸秘密哈希作为公开审计键。日志编码防换行注入。

## 03：生产入口和资源身份
梳理 read/search/git/文档转换/OCR/插件/MCP/子进程输出/缓存/报告导出各入口，分别登记路径检查、内容检查、脱敏消费者和未支持范围。生产装配缺策略时启动失败或拒绝相关读取，不静默放行；测试替身必须显式隔离。
对已登记的受保护资源建立本地身份集合并比较硬链接身份；不递归扫描整台电脑找别名。身份解析异常不作安全结论；处理检查后替换，通过已验证句柄/读取后身份复核等机制防止 TOCTOU。策略变更或内容变更须使缓存失效。
归档/图片不因文本扫描未命中当安全；首版外发只允许已扫描结构化文本生成的内容，不自动带入任意附件、远程图或本地图片。

## 04：通用外发门禁和证据
外发门禁绑定来源项目、内容 revision、目标账户/设备、授权范围、规则版本；检查内容和最终导出元数据。脱敏导致内容变化要生成新 revision 并重走授权绑定。未认证、扫描未完成、来源无权、设备解绑均阻断。
产出公共调用链清单和静态反例记录；不在公开文档出现客户端布局、私有实现路径或用户真实信息。

## 05：凭据类型覆盖表（2026-10-28 补充，必做）

本节细化 02，不新建第二套扫描器。交付同目录 `SEC02_CREDENTIAL_COVERAGE.md`，每类列明：规则 ID/版本、格式依据及核对日期、裸值识别能力、字段/路径上下文要求、正例与相似非秘密反例的夹具 ID、已接入口、限制及验证状态。厂商格式变化时更新规则与覆盖记录，不把固定长度猜测当成永久规格；格式依据使用官方公开资料，不用真实凭据查询服务。

| 必须登记的类别 | 检测和隔离要求 |
|---|---|

| GitHub/GitLab 与包仓库令牌 | 登记经典及细粒度/新式 token、npm 等已支持仓库凭据；覆盖普通文本、配置字段、认证 URL，不只识别旧前缀。 |
| 云服务凭据 | 登记 AWS 长期/临时访问标识、secret/session token，以及已接入 Azure/Google 等凭据；区分可识别标识与无固定格式秘密，关联字段可加强判定，不要求同一文件必须同时含完整凭据对才阻断已识别秘密。 |
| HTTP 与会话认证 | Authorization 的 Bearer/Basic、敏感 Cookie/Set-Cookie、OAuth access/refresh token、JWT 形态；Basic 编码不视为脱敏。JWT 结构不证明其有效，也不能因签名未验证就当安全。普通非认证 Cookie/标识保留明确反例。 |

| 数据库、消息服务与 webhook 凭据 | 含密码连接串、已接入服务令牌、带签名/鉴权查询参数的 webhook 或访问链接；普通无认证 URL 不一律判秘密。参数名称与已知服务结构参与判定。 |
| 无固定格式秘密 | 密码、客户端 secret、自定义 API key、随机 token；结合字段和受保护来源判定，不能用正则或熵声称识别全部裸值。明确列出无法仅靠内容识别的情况及对应隔离措施。 |

## 06：类型 × 模型可见通道矩阵（必做）

在覆盖文档中以 05 的类别为行、下列通道为列，登记实际生产调用链和结果；共用扫描器可复用规则夹具，但每个通道仍需自己的最终出口证据，不能用扫描函数结果替代生产接线。

- 文件全文、范围读取、搜索命中及前后文、目录元数据；分段读取不能绕过敏感资源判定。
- Git diff/show/log、命令 stdout/stderr、异常和退出诊断。
- 插件/MCP 工具结果、网络响应、文档转换、OCR、归档解析；未支持格式标 incomplete，不伪称 clean。
- 缓存命中、恢复记录、Agent 汇报/反馈、摘要与长期记忆读取。
- 模型请求最终装配出口、日志/诊断导出和授权范围内的外发出口。

每格记录入口函数→检测器→结果消费者→最终模型/外发出口、策略版本、预期拒绝或脱敏行为、当前证据状态；不存在的通道写 not-applicable 并附检索依据，不编造实现。模型读取阻断与日志脱敏分别验收。可信网络适配器发送给目标服务的认证头属于受保护认证通道，不得误送模型或转发到无关目标。

待验证场景必须包括：裸值/字段值、长文件尾部、分块边界、多字节字符、转义与换行、受支持的编码转换、旧缓存、重启恢复、策略缺失、扫描异常、超限、读取中资源替换、符号/硬链接别名。转换与解码有界，不递归尝试无限编码；不能由模型声明“已解码安全”。扫描通过的字节/版本与实际返回对象必须一致，禁止检查 A 后返回 B。

执行本卡仍不要求编写或运行测试；上述是必须交付的验收矩阵及后续验证条件，不得填写虚构的通过记录。若后续另获验证授权，只用人工构造的无效凭据和本地假服务，必须观察最终模型请求/工具返回/外发记录中的零泄露，而不是只断言扫描器返回 sensitive。

## 07：凭据隔离与最小读取能力（必做）

- 凭据解析由可信本地适配器完成；工作 Agent 仅获得不含秘密的账户/凭据引用。引用须绑定服务和操作范围，不能变成任意目标请求的通用认证能力。
- 子进程环境采用允许列表，不默认继承宿主凭据环境变量；shell、插件、转换器和模型生成脚本不持有凭据库访问权。检查环境变量、命令行、工作目录、标准输入及错误返回，避免通过诊断输出泄露。
- 对通用 shell 落实操作系统可执行的文件/进程隔离；仅检查模型工具参数不算隔离。所在平台无法隔离凭据资源时，拒绝具有该访问能力的通用执行路径并明确标记能力缺口，不用提示词代替保障。
- 认证请求凭据只发给绑定的合法服务；重定向或目标变更重新校验，不携带认证信息跨目标透传。不把请求头、SDK 配置、原始异常、进程转储或完整环境写入日志/模型结果。
- 本地扫描器检查正文不等于允许模型读取正文。命中/未完成/错误均不向模型返回原文；扫描暂存域对工作 Agent 不可读。禁止为了建立匹配库而遍历用户真实凭据或把真实秘密送入模型。
- 继承全模式敏感内容禁读规则：放权、会话提权、上级批准及“测试用途”不能绕过。无固定格式秘密主要依赖隔离，不宣传内容扫描能做到绝对识别。

实施顺序：01 → 02（含 05 类型表）→ 03（含 06 通道清单、07 隔离）→ 04。覆盖矩阵逐步补全；任何一项只有接口、空回调或注释而无执行消费者，保持未完成。交付时区分“常见类型检测覆盖”“通道接线覆盖”“凭据隔离边界”三个结论，不能合并成笼统的安全通过。
