## 2. UX-02-01：先修导航与页面切换

固定布局为：左项目导航 + 右工作区；右工作区由共享标题导航、当前页面、按需详情组成。

- 将项目名、会话/任务/成果/历史标签、待处理按钮移出 `chatPanel`，置于右工作区的固定共享标题栏。进入任意页面后这些入口仍可操作。
- 主页面状态只允许 `conversation / tasks / artifacts / history / pending / settings` 之一；新增一个统一页面切换函数，由其处理显隐、当前标签、焦点和返回位置。禁止各按钮分别隐藏互相重叠的一组容器。
- 切页保留草稿、各页滚动位置和筛选条件。返回会话不能自动提交草稿或恢复执行。
- 普通页面移除“更多”；恢复入口归入“历史 → 恢复记录”，用量归入“应用设置 → 用量与运行帮助”，授权/安装/澄清/验收归入待处理中心。
- 删除旧更多按钮事件绑定与全量遍历 `main.children` 搬运逻辑；使用固定 DOM 容器和稳定 ID。旧内部跳转调用改为统一切页函数，不保留点击隐藏按钮的转跳方式。
- 没有选中项目时仍能打开应用设置、创建/选择项目；项目专属页面显示“请先选择项目”，不得留空或借用上一个项目的数据。
- 异步返回绑定发起时的项目/会话标识；用户已切换目标时丢弃旧结果的界面更新，不能显示到新项目。

交付：共享导航、统一页面状态、明确的旧入口迁移表。所有中心页面均有返回会话入口，但不强制先返回才能切页。

## 3. UX-02-02：完整修复设置分类与作用范围

设置采用左分类、右内容的独立页面，不使用无限长锚点页面。当前仅显示一个分类，分类按钮标明选中状态；第一次打开显示常规，后续打开恢复最近分类。

固定分组如下：

| 范围及入口 | 分类 |
|---|---|
| 左侧底部“应用设置” | 常规与外观、模型账户、默认权限模式、上下文默认值、通知、用量与运行帮助、数据与备份、实验功能、帮助与关于 |
| 项目标题菜单“项目设置” | 文件夹授权、Agent、工作流与工具、项目权限、工作时段、项目上下文 |
| 会话标题“会话设置” | 输入策略、当前模型、临时权限、当前上下文 |

- 每页顶部显示作用范围、当前项目/会话名称及继承来源。只有现有后端支持覆盖时才允许编辑覆盖值；否则显示“继承应用默认值，当前不支持单独覆盖”。不得自行增加新配置协议。
- Agent、工具、用量、帮助等现有区块必须有真实显示位置；不得留在关闭的旧 `dialog` 中再使用 `scrollIntoView`。
- 权限组归入权限类，预算归入上下文类，不再显示混合的“上下文与权限组”分类。
- 事件初始化一次；打开设置仅选页、刷新数据与聚焦。保存请求进行中禁用重复提交；失败保留输入并显示原因。
- 离开有未保存修改的设置页时，固定提供“保存并离开 / 放弃修改 / 留在此页”；保存失败则留在当前页。不能无提示丢失用户编辑。
- 去掉普通帮助页中的内部协议、调试注入说明；用户可见故障说明和脱敏支持包入口保留。后端缺失时明确不可用。

交付：真实分类页面、范围标识、完整功能迁移；没有一个分类只指向隐藏内容。

## 4. UX-02-03：简化模型配置与成果使用

### 模型账户

- 默认流程固定为厂商 → 密钥 → 模型 → 保存；厂商使用已有预设，不联网抓取或安装依赖。
- 端点、协议、凭据引用、上下文窗口、最大输出和能力声明放入“高级配置”。选择自定义厂商时自动展开高级配置并显示必填项。
- 模型清单来源使用已有接口；没有清单接口时允许填写模型标识，不伪造可选模型或声称连接成功。
- 保存只显示“配置已保存”；仅在已有真实连接结果时显示连接状态。保留既有防断连确认和只写密钥规则。

### 成果页

- 默认按成果卡/列表呈现：名称、类型、来源任务、更新时间、打开按钮。选中后详情展示路径、来源、预览和差异等已有能力。
- 只把现有产物记录认定为任务成果，不将整个项目文件树自动当成已产出的结果。
- 没有产物记录接口时显示“暂无可展示的任务成果”，保留“浏览项目文件”；文件列表明确叫“项目文件”，不能伪装为成果。
- 文件树为辅助入口；可预览格式使用现有预览能力，其他格式提供已有的打开/下载能力，不新建全能编辑器。
- 打开、下载、编辑仍遵循已有路径边界与授权，不因为 UI 改版获得额外权限。

交付：低门槛账户配置与面向成果的页面；不削减高级配置和文件访问能力。

## 5. UX-02-04：历史阅读与新消息行为

- 更新前距底部不超过 80 CSS px，且用户没有正在使用的文本选区时，更新后自动跟随到底部。
- 其余情况保留首个可见消息的稳定标识及相对偏移；降级到保留滚动位置。显示“新增 N 条消息”按钮，点击才定位到底部并清零。
- 按稳定消息 ID 去重计数；同一流式消息的多次更新不重复计数。
- 用户主动发送成功后允许定位自己的新消息；后台通知和刷新不能强制滚动。切换项目时不继承另一项目的新消息计数。
- 查看历史、展开工具步骤、复制内容均不能触发任务续跑或模型请求。工具调用默认摘要，详情按需展开。
- 所有消息追加、批量刷新、通知追加使用同一滚动控制模块，不保留散落的无条件 `scrollTop = scrollHeight`。

交付：统一滚动控制、新消息提示、阅读位置保留。

## 6. UX-02-05：主题、详情与键盘行为

- 保留 UX-01 的尺寸和主题基础，将设置页、选中项、通知、表单、授权卡的固定颜色统一替换为语义 token：背景、面板、正文、次要文字、边框、选中、成功、警告、危险。
- 风险状态同时提供文字或图标说明，不仅靠红黄绿区别。内部 UUID 不作为普通标题，详细身份仍可在详情复制。
- 宽度达到 1100 px：详情为非模态右侧栏，默认 360 px、可调整 320–420 px，不显示遮罩，不锁住会话。
- 低于 1100 px：详情为模态抽屉，宽度 `min(360px, 92vw)`，显示遮罩、限制焦点、Esc 关闭、关闭后归还触发控件焦点。
- 低于 900 px：项目导航也使用抽屉；项目抽屉与详情抽屉互斥。弹出授权确认前关闭普通抽屉，避免多层遮挡。
- 窄屏设置采用“分类列表 → 单分类内容 → 返回分类”的单栏布局，不强挤左右两栏。
- 全部头像右键操作须有普通按钮或菜单入口；保留右键作为快捷方式，不把任何设置仅藏在右键内。
- 背景模式切换不重新载入会话、不修改权限配置；主题、关闭详情和调整宽度均仅是视图状态。

交付：统一主题与宽窄布局代码、清楚的焦点和返回行为。

## 8. 模块拆分与工作节奏

实施 01 时建立 `packages/gui/src/server/ui/`，使用现有 TypeScript 导出字符串片段的方式组织页面，不新增构建工具：

- `navigation.ts`：共享导航模板、页面切换脚本。
- `settings.ts`：分类模板、设置切换与初始化脚本。
- `conversation-scroll.ts`：滚动跟随、锚点和新消息计数脚本。
- `detail-panel.ts`：详情模板、宽窄屏交互脚本。
- `theme.ts`：共享 CSS token 与响应式样式。

`gui-server.ts` 保留服务路由与页面装配，对迁出的模板/脚本调用上述模块。其他业务脚本保持原位，不顺带全量重构。模块不得反向导入 `gui-server.ts`；涉及动态文本继续安全转义、使用 `textContent`，不得为拆分引入未经转义的 HTML。
