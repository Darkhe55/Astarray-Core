## 目标和固定语义
恢复既有主干：用户任务 → 主 Agent 沟通与方案 → 次级个体任务偏序集 → 就绪任务组 → 下级执行 → 独立审查/集成 → 来源明确的反馈与归档。小型明确任务可由用户显式直投次级，不得将所有任务默认为直投。

统一任务序列是权威调度来源，保留用户最高优先层、偏序依赖与合法插入。一次向模型送入一组任务；运行中补充是对当前任务组提出带版本的插入，不另建引导/队列/智能模式。窗口是准入/上下文容量机制，不是第二调度器。不要以恢复设计为名删除已批准的后续改进。

## 静态基线与风险
- main-controller.handleUserMessage 默认每条消息创建 mission，decomposePromptForScriptedRun 固定 T-001：缺少默认规划与持续项目调度的体现。
- application-runtime 的 SecondaryContinuousDispatchLoop 使用 dispatchChain 返回 false、占用数返回 0：该路径不能算持续调度已接。
- respondInPonderMode 每次新建随机主 Agent ID：需贯通稳定个体与运行身份，不能直接断言全系统历史已丢失。
- 偏序、个体记忆、反馈进程、上下文节点及 Git 组件仍存在，必须接主干而非重写。
- 上述是代码路径证据，不证明所有替代入口都失效，也不能归因为某个模型。
