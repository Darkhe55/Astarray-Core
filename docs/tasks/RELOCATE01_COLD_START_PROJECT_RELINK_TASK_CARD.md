## 1. 范围、依赖与非目标

解决冷启动时目录搬迁、路径失联、同路径换项目、复制目录导致历史对不上，以及重新关联后的安全恢复。项目身份独立于路径，不依赖目录名称或绝对路径认领历史。

**工作中迁移排除，留待后续讨论。** 本卡不实现运行中搬目录或热切换。若有活动执行器或写入租约，拒绝关联提交并提示结束运行后重试，不抢占、不强停其他实例；新客户端冷启动不代表旧执行器已停止。

不自动搬移、合并或删除目录，不改写源码、配置、命令或历史原文，不做全盘搜索、云同步或移动端。历史展示复用现有入口，只补本卡必需的待关联状态和已存历史索引查看，不隐含解除其他历史功能的暂缓决定。

实施前完整读取 AGENTS 指定治理文档、本卡和 PRODUCT_INTEGRATION_ROLLOUT；核查 T12A/T12A-R1 恢复、PROJECT-01 注册/授权、工作区边界、备份及历史存储的实际接线。优先复用，不因历史 done 推定本需求已实现。

## 2. 身份与冷启动状态

- 复用稳定 `projectIdentifier`，名称仅用于展示；位置登记独立保存设备、当前根目录和位置 revision。先审计既有 ID 是否由路径派生，不直接全仓换 ID。
- 项目内资源优先使用项目 ID + 相对路径。旧历史缺少稳定 ID 时，经用户明确关联并保留旧索引；版本迁移先备份，失败不破坏旧格式读取。
- 项目标识可能随复制目录被复制，ID/Git 信息仅为一致性证据，不构成未知新位置的自动授权；同名目录和同 Git 远端更不能单独证明身份。
- 位置状态与任务状态分离；查看历史不启动模型、不恢复任务、不执行历史命令。

| 情况 | 行为 |
|---|---|
| 原路径可访问且身份一致 | 加载历史，进入只读恢复对账，不直接重跑 |
| 路径不存在、设备未挂载或无访问权限 | 显示具体原因，待关联；不自动新建空目录 |
| 原路径存在但身份不同 | 阻止套用旧历史及项目执行 |
| 多个候选有相同身份 | 用户选择继续原项目或独立打开，不自动猜测 |
| 标识缺失、登记损坏 | 进入旧格式关联/恢复流程，不伪称验证成功 |

路径失联不得把任务标为 done/failed，也不自动归档。用户暂不关联时可查看仍可访问的已存历史；只阻塞受影响项目。存档本身不可访问时如实提示，不伪造历史可用。

## 3. 重新关联流程

1. 用户选择新目录为默认入口；可授权 Agent 在指定范围查找候选或提议映射，不进行默认全盘扫描。查找授权不等于全文读取、确认关联或扩大项目权限。
2. 本地控制面仅核验必要元数据，展示简短独立确认卡：项目名称/ID、旧位置、新位置、匹配或冲突原因、影响。重定位与新增目录或跨项目授权分开，不捆绑批准。
3. 认证用户确认后，以预期位置 revision 提交；执行前重新检查真实路径与身份，防止确认后目录或符号链接被替换。未知新位置不能由模型代确认，放权模式也不自动作出身份关联决策。
4. 原子更新登记并保存旧根、新根、revision、确认来源与时间。重复请求幂等，冲突 revision 拒绝并刷新确认；失败保留旧登记或明确待恢复，不出现半提交，不覆盖新目录原有内容。
5. 独立打开副本使用新项目身份及独立历史域，不继承未决任务、许可、临时权限或 Agent 活跃身份，不改变原项目；不能安全建立独立身份时保持阻塞，不能共享历史。关联过程不自动复制历史或记忆。

归档是用户不再继续项目时的独立选择，不是关联失败的兜底，更不等于删除历史。

## 4. 路径映射与恢复门禁

- 映射绑定项目、设备和位置 revision，已确认的历史根直接解析到当前根；拒绝循环、歧义和不明确的重叠规则，不形成无限链。
- 仅解析 schema 明确声明的结构化资源路径和受控历史链接。历史消息、日志、证据、源码、配置、任意命令字符串不自动替换；界面可另示当前位置。
- 保留原请求路径及实际解析路径/revision，按既有规则脱敏。重新执行真实路径、符号链接、敏感路径和当前权限检查；旧授权不直接转成新位置许可。
- 外部文件、其他项目根、已注册的嵌套项目不随当前项目自动纳入。历史旧根被另一项目使用时，映射只在原项目上下文生效，不截获新项目访问。
- 复用跨平台规范，Windows 盘符/UNC 与 POSIX 大小写各按语义处理；不能以字符串前缀判断包含关系，如 `old-project-extra` 不属于 `old-project`。
- 关联后先加载历史及任务列表，再复用恢复流程只读核对文件、Git、Provider 未决操作及产物。原目录失联不等于旧操作无副作用。
- 已确认完成的不重放；未知非幂等副作用 blocked，不能因换路径重试；旧一次性许可和临时提升不恢复，身份/handoff 沿用既有恢复契约。
- 检查点无法解析、目录内容变化或产物哈希不符时输出差异，不自动覆盖。门禁满足后才按既有恢复策略继续，不把用户确认位置当成批准执行所有旧任务。

## 6. 测试方案

### 单元、组件与故障注入

1. 覆盖第 2 节所有状态；同名/同远端不自动关联，旧格式迁移失败仍可读取原索引。
2. 拦截伪造确认者、超范围搜索、把候选选择当全文读取授权；多个相同 ID 副本需明确选择。
3. 重复提交幂等、并发确认 revision 冲突、确认后路径替换、符号链接逃逸、映射循环/前缀误匹配均有反例。
4. 多次迁移历史路径可解析；源码、日志、命令正文哈希不变；路径映射不截获其他项目。
5. 映射后敏感读取仍被禁止，读/写分别重新校验权限，旧临时权限与一次性授权不恢复。
6. 在备份、登记写入及索引更新各阶段注入失败/崩溃，重启可恢复，无半提交、历史丢失和重复副作用。
7. 完成操作不重放、未知副作用阻塞、陈旧产物不覆盖；单项目待关联不阻塞其他项目。
8. 活动执行器或租约存在时不能提交；独立副本不继承历史域、任务或记忆所有权。

### 产品、人工与 tarball

在临时目录 A 创建真实任务/历史 fixture，退出第一进程；由测试宿主移至 B，第二进程冷启动，经真实公共入口确认关联，再读取历史并运行受控操作。分别覆盖存档随目录搬迁、存档独立保存两类布局，不依赖第一进程内存。测试宿主移目录不代表实现工作中迁移。
