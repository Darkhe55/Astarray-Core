# ADR-0124 任务卡索引与台账的只读交叉核对（R41）

- 状态：已采纳（脚本扩展 + 生成报告）
- 日期：2026-10-29
- 来源：[NEXT60_PLAN_2026-10-29](../tasks/NEXT60_PLAN_2026-10-29.md) R41、ADR-0123
- 相关：`TASKCARD_BACKLOG_2026-10-17.md`（人工台账）

## 1. 背景

R40 的索引只统计文档事实，**没有**与 `TASKCARD_BACKLOG_2026-10-17.md` 声称的
"`docs/tasks/*.md` = 42 张卡"做任何核对。两边是否还一致，只能人工记。

## 2. 变更（冻结）

1. 脚本增加**只读**交叉核对段：
   - 对每个文件用 `git log --diff-filter=A -1 --format=%as` 取**首次提交日期**；
   - 列出**晚于基线 2026-10-17** 的文件及日期；
   - 打印"基线 42 / 当前文件数 / 晚于基线的文件数"。
2. **不判断**哪份文件算"卡"（计划/索引/矩阵/归档都在 `docs/tasks/` 下）；
   差异只用于人工核对，**不构成完成或未完成结论**。
3. 路径范围从 `docs/tasks/*.md` 扩到 `docs/tasks/**/*.md`（含 `accepted/`、`archive/`）。

## 3. 生成物

`docs/reports/TASKCARD_STATUS_VIEW_2026-10-29.md`（已重新生成，含"与台账交叉核对"一节）。

## 4. 局限（如实）

- **移动/归档会刷新"首次提交日期"**：`docs/tasks/archive/**` 的文件显示为 2026-10-29
  （实际是移动日），因此"晚于基线"不等于"新写的卡"。
- 基线数字 **42** 是 2026-10-17 台账里的历史断言，脚本**不验证其正确性**。
- 不做状态映射（台账没有逐卡 status 表，只有叙述）。

## 5. 验证状态

- 脚本**已运行**（只读文档 + 只读 git 日志）：exit 0，报告已更新；
- 未跑产品测试、未改任何卡；
- `typecheck` / `eslint` / `build` 不受影响（`.mjs` 不进构建）。
