# ADR-0129 文档死链检查（R57）

- 状态：已采纳（只读脚本 + 一次修复）
- 日期：2026-10-29
- 来源：[NEXT60_PLAN_2026-10-29](../tasks/NEXT60_PLAN_2026-10-29.md) R57
- 相关：ADR-0123/0124（文档索引/交叉核对）

## 1. 背景

本轮新增了大量报告、ADR 与卡片链接；文件移动或相对路径写错都会让读者点到不存在的文件。
此前**没有任何机制**检查相对链接。

## 2. 交付

1. `scripts/manual/docs-link-check.mjs`（**只读**）：
   - 扫描 `docs/**/*.md` 与仓库根 `*.md`（忽略 `node_modules`/`dist`/`.git`/`.tmp`）；
   - 抽取 `](relative/path)`，跳过 `http(s)`、`mailto:`、纯锚点；
   - 去掉 `#fragment` 后解析目标是否存在；输出死链表与计数；
   - **exit 0 无死链 / 1 有死链**（便于机制化复跑），**不修改任何文档**。
2. 首次运行发现 **17 条死链**，全部修复后复跑为 **0**：
   - `PLAN_STATUS.md` 10 条：链接写成 `astarray/docs/...`（从仓库内应为 `docs/...`）；
   - `docs/adr/0125` 1 条：`EVIDENCE_INDEX_2026-10-29.md` 应在 `../reports/`；
   - `docs/reports/REMAINING_ITEMS_PRIORITY` 1 条：`../PLAN_STATUS.md` 应为 `../../PLAN_STATUS.md`；
   - `GOAL02` 卡 3 条、`NEXT60_PLAN` 2 条：`../../reports/` 应为 `../reports/`。
3. 生成 `docs/reports/DOCS_LINK_CHECK_2026-10-29.md`（修复后复跑结果）。

## 3. 结果（真实输出）

- 扫描 **418** 个 Markdown、检查 **352** 条相对链接；
- 修复前 **17** 条死链，修复后 **0** 条（exit 0）。

## 4. 未完成（如实）

- **只检查存在性**：不校验链接内容是否与标题一致，也不校验锚点（`#section`）是否存在。
- **不检查外部 URL**（跳过 `http(s)`），避免联网。
- **不是构建期守卫**：没有 CI 钩子，需要手动运行。
- **每次新增文档仍可能再引入死链**（本轮只清零一次）。

## 5. 验证状态

脚本**已运行**（只读文件系统）：修复前 exit 1（17 条），修复后 exit 0（0 条）；
**未运行产品测试**；`typecheck`/`eslint`/`build` 不受影响（`.mjs` 不进构建）。

## 6. 追加修复（R57 收尾）

首次修复后复跑仍报 2 条"死链"，实为**文档里的示例文本**（`](相对路径)`、`](relative/path)` 写在行内代码里）。
脚本已改为**先剔除围栏代码块与行内代码**再抽取链接；复跑 **419 文件 / 353 链接 / 死链 0（exit 0）**。
这属于脚本自身的假阳性修复，**不是链接目标真的缺失**。
