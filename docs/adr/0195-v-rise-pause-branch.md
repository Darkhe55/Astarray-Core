# ADR-0195 V 上升 ⇒ 暂停分支的确定性验证（R137，2026-11-03）

- 状态：**已覆盖**（预置陈旧 V 的状态级夹具；真实图操作无法自然构造该分支）
- 来源：用户"继续"（补 R134 的暂停分支）
- 相关：ADR-0192（自动重算 V）、ADR-0194（确定性演练）

## 1. 为什么真实图操作构造不出来

当前安全的图操作只有：注入（新任务不在映射）、删除 **pending 叶子**、修订 pending 内容、
重连 pending/blocked 依赖。它们都**不能**让"已完成且有证据的映射任务"失去证据：

- 删除只允许 pending（已完成任务不可删）；
- 重连不改状态；
- 注入任务不在原映射里，V 不变。

因此"V 上升 ⇒ 暂停"在真实操作下几乎不可达——它是**防御性分支**。

## 2. 确定性验证方式

在确定性演练（ADR-0194 的权限阻塞夹具）中：

1. 目标映射 `req-1 → [T-001]`，`T-001` 因权限询问 blocked（重算 V=1）；
2. **测试目录内预置** `lastPotentialValue=0`（模拟"上次曾有证据"）；
3. 注入 `T-99` 触发图变更 ⇒ 运行时重算 V=1 ⇒ 1 > 0 ⇒ **暂停 + requiresReplanning**；
4. 断言：`pauseReason` 含 `V 上升`、`lastPotentialValue=1`。

预置只改测试状态文件，不改产品代码；语义上等价于"状态陈旧/证据被外部移除"。

## 3. 验证

```
graph-change-deterministic-drill.test.ts → 2/2
  ① 正常状态注入：接受、审计落盘、不暂停、V=1；
  ② 预置陈旧 V=0 后注入：V 重算为 1 ⇒ 暂停 + requiresReplanning + pauseReason 含"V 上升"。
tests/core --maxWorkers=2 → 471 files / 3650 tests 全通过
typecheck / lint / build → 全绿
```

（首轮曾因子目标预算 10 被权限重试耗尽，暂停原因被预算覆盖；把夹具预算调至 50 后稳定。）

## 4. 仍未覆盖

- 真实业务路径下的 V 上升（需"已完成映射任务失证"的产品语义，例如删除已完成任务/撤销收据）；
- 删除/修订/重连各自的联动演练（目前只演练注入）；
- 暂停后的恢复流程。
