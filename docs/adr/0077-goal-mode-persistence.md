# ADR-0077 目标模式持久化、恢复对账与实验退出（GOAL-02-03）

- 状态：部分采纳（持久化 + 恢复对账 + 关闭标记；未接派发、无 UI）
- 日期：2026-10-28
- 来源：[GOAL-02](../tasks/GOAL02_BOUNDED_GOAL_STABILITY.md) 检查点 03
- 相关：ADR-0075（契约与 V）、ADR-0076（门禁）

## 1. 背景

GOAL-02-01/02 的状态都在内存里：重启后累计预算、暂停原因、当前组、V 依据全部丢失；
也没有"关闭实验"的安全语义（停下新增派发但保留历史）。恢复时若直接重跑，
可能重复副作用。

## 2. 契约（冻结）

1. **持久化字段**（`<state>/goal-mode/<goal>.json`）：目标/契约版本/owner/原始要求引用、
   **V 的逐项依据**（每条要求的权重、证据、剩余贡献）、last-known V、当前组与开始时间、
   累计工具调用与成本、暂停原因、证据缺口、`requiresReplanning`、实验关闭标记与关闭时间、
   门禁快照、`documentRevision`。
2. **恢复先对账**（`evaluateResume`）：
   - 有在途组 ⇒ **`reconcile-first`**（不知道副作用是否发生，**禁止直接重跑**）；
   - 暂停/需重规划/实验关闭 ⇒ `stay-paused`（带原因与缺口）；
   - 否则 `resume`，只带 last-known V（**不重算、不宣称稳定**）。
3. **版本不串**：持久化的 `contractRevision`/`sourceRequestReference` 与当前契约不一致 ⇒
   直接拒绝（旧版本的预算/暂停结论不得套到新目标上）。
4. **实验退出**：`closeExperiment` 只置标记 + 记录时间 + 写暂停原因；
   **保留**任务、历史、限制与已执行结果（不清空、不回滚）。
5. **状态视图**：`describeStatus` 返回状态、判据缺口数、资源消耗、下一检查点；
   `stabilityGuarantee` **恒为 `"none"`** —— 不返回未经证实的稳定性保证。
6. **原子性**：写入走 `writeAtomicJson` + 互斥；读取走备份恢复；损坏文档按"无状态"处理
   （不伪造历史）。

## 4. 未完成（如实）

- **未接进恢复流程**：`resumeMission` 不会调用 `evaluateResume`；目标模式重启后不会自动对账。
- **未接进派发**：门禁仍未接线（沿 ADR-0076 结论），因此"关闭实验 ⇒ 停止新增派发"目前
  **只是数据标记**，没有执行侧保障。
- **没有 UI/CLI**：看不到状态视图，也没有关闭实验/确认对账的入口。
- **成本单位未定义**：`consumedCostUnits` 只是字段，没有计价来源。
- **崩溃窗口**：`beginTaskGroup` 与真实副作用不是同一事务；崩溃后只能靠"在途组"提示对账，
  **不能自动判定副作用是否发生**。
- **未验证**：没有跑过"有在途组 ⇒ reconcile-first""版本不一致 ⇒ 拒绝""关闭实验后不恢复
  且历史保留""状态视图不含稳定性保证"任何一条。
