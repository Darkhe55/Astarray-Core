# GOAL-02 内核 / UI 职责划分与缺口（2026-10-30）

> 问题：按任务卡，**闭环的内核职责**能否在公开核心仓库完成，UI 职责交给 UI 仓库？
> 结论先行：**内核职责目前无法闭合**——卡要求的能力有一部分已在核心实现，但**入口、映射、
> 完成耦合、失活/归档、运行中暂停**这五类仍缺；UI 侧需要的读取/操作接口也因此不存在。
> 本文件只做核对，**不改代码**。

## 1. 职责划分（本文件采用的边界）

**内核（公开仓 `astarray/`）**：谁有权设目标、目标与任务的映射、推进约束与暂停、完成判定、
恢复对账、失活/归档、状态/审计数据。
**UI（私有仓 `astarray-ui/`）**：目标的对话呈现与确认、进度（V/缺口/预算）展示、
暂停/恢复/关闭操作、历史与通知。
**原则**：UI 只调用内核接口，不自行判定"目标是否达成"，也不保存唯一事实。

## 3. 内核缺口（必须在公开仓补，UI 无法替代）

| # | 缺口 | 为什么是内核职责 | 建议量级 |
|---|---|---|---|
| **K1** | **目标设立入口**：把"用户对话里说的目标"变成 `GoalContract`（含 requirements），且必须**用户确认**、模型只能提议 | 契约合法性、来源绑定、拒绝模型自改 | 中 |
| **K2** | **requirements ↔ 任务节点映射**的写入/更新 | 决定 V 是否有意义 | 中高 |
| **K3** | **契约变更 API**（新 revision + `supersedesRevision` 校验 + 预算不重置） | 版本合法性与"不降判准" | 中 |
| **K4** | **派发前评估安全不变量** | 卡的硬要求："进展不得抵消越权" | 低（接线） |
| **K5** | **证据失效检测接线**（组边界/外部变化 ⇒ 暂停 + 重规划） | 负反馈的核心 | 中 |
| **K6** | **`pauseConditions` 评估** | 卡 01 契约字段必须生效 | 低 |
| **K7** | **完成判定耦合**：`complete-mission` 前要求"所有 requirement 有证据"（V=0）+ 收据/裁决齐备 | 否则"完成"与目标无关 | 中 |
| **K8** | **目标失活/归档 API**（"移除"= 不再参与派发；历史/限制保留） | 卡 03 明确禁止清除历史 | 低 |
| **K9** | **状态/审计读取接口**（`describeStatus` 接 CLI/宿主） | UI 的唯一事实来源 | 低 |
| **K10** | **运行中暂停**：在组边界评估门禁，不通过 ⇒ 停调度 + 置 blocked + 反馈 | 现在只在启动前评估，"阻塞自动停止"不成立 | 中高 |
| **K11** | **预算取更严**（目标上限 vs 调度上限） | 卡 02 明确要求 | 低 |
| **K12** | **目标生命周期事件**（创建/暂停/恢复/关闭）供 UI 订阅 | 无事件则 UI 只能轮询 | 低中 |

## 4. UI 仓库职责（`astarray-ui/`，本次未改动）

> 现状：UI 仓库的 `docs/tasks/OCT28_REVIEW_AND_EXTENSION_INDEX.md` 只在索引里提到 GOAL-02，
> **没有目标模式的 UI 任务卡**（检索 `目标模式|goal-mode|GOAL-02` 仅命中该索引）。

UI 需要（依赖 K1/K8/K9/K12）：
1. 目标创建/确认界面（展示模型提议的 requirements、范围、预算、截止）；
2. 进度视图（V、逐项依据、证据缺口、预算/组计数）；
3. 暂停/恢复/关闭操作（调用内核接口，不自行判定）；
4. 历史与审计（创建、变更、暂停原因、关闭时间）；
5. 通知（暂停/阻塞/关闭事件）。

## 5. 结论

- **内核职责目前不能闭合**：K1/K2/K3/K7/K8/K10 是关键缺口，K4/K5/K6/K9/K11/K12 是"已实现但未接线"或"低量级补齐"。
- **UI 职责无法先做**：没有 K1/K8/K9/K12，UI 没有可调用的接口与事实来源。
- **建议顺序**：K9/K4/K6（低）→ K5/K11/K8（中低）→ K7（中）→ K1/K2（中高）→ K10（中高）→ K12/UI。
