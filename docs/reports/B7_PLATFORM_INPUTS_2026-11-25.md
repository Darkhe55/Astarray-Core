# B7（REMOTE-01 平台投递）所需资料清单

> 状态：**等待平台方提供**（2026-11-25）。用户已确认继续推进但平台资料未到位。
> 本文把"缺什么、要什么格式、缺了会卡住什么"逐项写清，收到即可接线；本仓库不预置任何真实凭据。

## 1. 测试租户（沙箱环境）

| 项 | 要求 |
|---|---|
| 平台名称 | 例：飞书 / 企业微信 / Slack / 自建网关 |
| 租户标识 | `tenantIdentifier`（测试租户，不与生产共用） |
| 接入方式 | Webhook / Bot 应用 / 自建服务；给出**测试租户**的调用地址 |
| 凭据形态 | 明确是"长期 token / 短期 token + 刷新 / 签名密钥"哪一种 |
| 获取方式 | 我们如何注入（环境变量名 / 凭据引用 ID / 本地文件）——**不要把真实凭据写进仓库或聊天** |

**缺了卡住**：无法发起任何真实投递；REMOTE-01 只能停留在契约与假适配器层。

## 2. 签名算法与测试向量

| 项 | 要求 |
|---|---|
| 算法 | 例：HMAC-SHA256、RSA-SHA256、Ed25519 |
| 待签名字符串 | 精确拼接规则（时间戳、nonce、body 是否包含、分隔符、编码） |
| 时间戳格式 | 秒/毫秒、时区、允许时钟偏移 |
| 签名编码 | hex / base64url |
| 测试向量 | **至少 1 组**：输入（含完整待签串）+ 密钥（测试密钥）+ 期望签名值 |

**缺了卡住**：签名函数无法验证正确性；只能"看起来对"，不能过验收。

## 3. 回执 API

| 项 | 要求 |
|---|---|
| 投递结果查询 | 同步返回（HTTP 状态/响应体字段）还是异步回调 |
| 幂等键 | 平台侧幂等键字段名与语义（同一键重复投递是否去重） |
| 成功/失败判定 | 哪些状态码/字段代表"已送达 / 已读 / 失败 / 未知" |
| 对端标识 | 回执里与请求关联的 ID 字段（用于关联本地 requestIdentifier） |
| 回调验签 | 回调是否签名、用什么算法、如何校验 |

**缺了卡住**：`acknowledged` / `outcome-unknown` 无法如实判定；只能保守全记 unknown。

## 4. 限流与重试语义

| 项 | 要求 |
|---|---|
| 限流维度 | 按租户 / 按会话 / 按用户 / 按接口 |
| 配额与窗口 | 每分钟/秒的条数，超限响应（状态码/错误码） |
| 重试建议 | 是否支持退避重试、Retry-After 头、最大重试次数 |
| 重复语义 | 平台是否保证"同幂等键只生效一次" |
| 熔断信号 | 哪些响应应触发本地熔断而非继续重试 |

**缺了卡住**：无法安全实现重试（可能重复外发）；REMOTE-01 的"重复投递不产生第二次副作用"无法验收。

## 5. 凭据注入方式

| 项 | 要求 |
|---|---|
| 注入点 | 环境变量 / 凭据引用（本仓库的 `protectedCredentialReferenceId`）/ 本地文件 |
| 读取时机 | 进程启动 / 每次请求 / 到期刷新 |
| 轮换方式 | 手工替换 / 自动刷新（刷新接口与失败语义） |
| 最小权限 | 该凭据允许的接口范围（只投递消息，不要管理权限） |
| 存储要求 | 是否允许落盘；落盘时的加密/权限要求 |

**缺了卡住**：无法通过"凭据不落仓库"的隐私门禁；也无法做凭据轮换与撤销验收。

## 验收口径（资料到位后）

1. 同一幂等键重复投递 ⇒ 对端只生效一次（平台侧回执证明）；
2. 断网/超时 ⇒ 本地记 `outcome-unknown`，**不**记 delivered；
3. 限流命中 ⇒ 按平台语义退避，不无限重试；
4. 回调验签失败 ⇒ 拒绝并记录原因，不污染本地状态；
5. 凭据不出现在日志/仓库/错误信息中（隐私检查脚本通过）。
